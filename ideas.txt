IDEAS / LATER
=============
Not in v1. Parked here so they don't get lost.

FILTERING
- Confidence score on the "is this a bank message" filter instead of yes/no
- Show messages that landed just below the threshold in a "maybe?" list
- Swipe left/right on those to narrow or widen the threshold
- Regex extraction templates for known HDFC formats so the AI is skipped entirely (filter 2)

LEARNING / USER CONTEXT
- Log every correction: what the app guessed, what the user changed it to, how many times
- Summarize repeated corrections into a short user profile ("small UPI payments to people = Misc")
- Feed that profile to the AI along with the last N corrections
- Wider built-in merchant list so common shops never need the AI

LOCATION
- Save last-known location with every transaction from day one (cheap, no GPS wake)
- Later: send it to the AI as extra context for categorization
- Pattern idea: Rs 50 near a train station at 9am to a random UPI id = travel
- Option: send place type ("near a station") instead of raw coordinates

CONTACTS (added after seeing real data)
- Match payee names against the phone's contact list
- "AARYAN JAIDEEP KANERIA" -> show as "Aaryan" with the contact photo
- Groups transfers by real person; makes the transfers view readable
- Needs READ_CONTACTS. Solves naming, not categorization.

WHAT THE REAL DATA SAID (3248 HDFC sms, Mar 2022 - Oct 2026)
- 6 regex templates extract 94% of real transactions, zero AI
- 918 distinct payee strings, but 187 repeat = 74% of money
- tag top 50 payees -> 66% of money; top 100 -> 78%; top 200 -> 88%
- nameless paytm QR codes = 0.8% of spending -> location layer is NOT worth building yet
- brand aliases are the real mess: SWIGGY has 14 spellings, ZERODHA 6, AMAZON 6
- sub-brands are distinguishable in the text: SWIGGY INSTAMART != SWIGGY
- contact names rarely match the bank's string: "AARYAN JAIDEEP KANERIA" is saved as
  "Kaneria", "ATHARV SALIL DESHPANDE" as "pande". So match on any shared word OR substring,
  show it as a suggestion, never as a fact. Low stakes: naming a vendor happens once.
